# Contributing

## Getting Started

Prerequisites: Node 25+, Bun (pinned via mise).

```sh
mise install
bun install
```

### Development Plan

Read **[`PLAN.md`](./PLAN.md)** before starting work. It defines the phased build order,
team task allocations (BE1/BE2/FE1/FE2), and dependencies between features.

**Check off tasks as you complete them** — update `PLAN.md` in your branch so the team
can track what's done. Use `- [x]` for completed items.

### Useful Commands

| Command | Description |
|---|---|
| `bun run dev:app` | Start Expo dev server (web) |
| `bun run dev:api` | Start wrangler dev for API Worker |
| `bun run check` | Lint → format:check → typecheck (must pass CI) |
| `bun run lint:fix` | Auto-fix lint issues |
| `bun run format` | Auto-format code |
| `bun run typecheck` | Type-check all packages |

### Project Structure

```
apps/app          Expo Router app (web + mobile)
apps/api          Cloudflare Worker API (Hono)
packages/db       D1 reset SQL
packages/shared   Shared Zod schemas & API contracts
```

## Commit Practices

### Update PLAN.md Before Each Commit

Before committing, ensure [`PLAN.md`](./PLAN.md) is up to date — mark completed tasks with `- [x]` so the team can track progress.

### No AI Attribution

Before committing, pushing, or opening a PR, remove any:
- **Co-Authored-By** lines from commit messages
- **AI-generated comments** (e.g. `// Generated by ...`, `// This code was ...`)
- **Other tool attribution** from code, commit messages, and PR descriptions

Keep commits clean of any AI tooling traces.

### Small, Focused Commits

No single commit should exceed **200 lines of diff**. Split larger changes into smaller, logically-scoped commits to keep reviews tractable.

### Commit Frequency

Commit and push **at least once per working session**. Frequent, small commits are preferred over large batch commits.

### Stay Synced

- **Pull before you push** — always run `git pull --rebase origin main` before pushing.
- **Keep your branch up to date** — rebase or merge `main` into your branch regularly to avoid conflicts.

### Conventional Commits

All commit messages must follow [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <subject>
```

**Types**: `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`

**Common scopes**: `api`, `db`, `ingest`, `map`, `docker`

**No descriptions** — one-line messages only.

Examples:
```
feat(api): add POST /notes endpoint
fix(db): correct POI coordinates migration
chore(deps): update expo to 54
```
